# Nova UI Kit 后续工作计划

> 版本：2026-07 · 状态：草案  
> 适用范围：Nova UI Editor（alpha）下一阶段迭代  
> 依据：README Roadmap、`output/goal-audit/`、`output/ui-audit/`、源码结构与最近提交方向

---

## 1. 背景与现状摘要

Nova 是一个桌面优先的可视化 Tauri 应用编辑器（Project / Design / Logic / Build 四模式），对标 Qt Creator / Qt Design Studio 的交互密度与工作流。当前处于 **active alpha**：本地实验可用，但项目 schema、生成输出与编辑器工作流仍可能快速变化。

### 1.1 已具备的能力

| 领域 | 现状 |
|------|------|
| 桌面壳 | Tauri v2、无边框窗口、自定义标题栏、Windows GUI release exe |
| 前端 | React 18 + TypeScript + Vite + Tailwind + Radix/shadcn 风格组件 |
| 设计 | 画布、组件面板、导航器、检查器、断点、布局、撤销重做、事件绑定 |
| 逻辑 | Rust command/module、事件绑定、状态补丁、诊断、source map、后端集成脚手架 |
| 构建 | 生成文件计划/落盘、就绪检查、exe/安装包、任务队列、运行日志 |
| 校验 | `scripts/` 下 9 个契约/冒烟脚本 + GitHub Actions |

### 1.2 主要债务与缺口（本计划的驱动因素）

1. **`BuilderShowcase.tsx` 过大**（约 5.5 万行 / 2.7 MB）：画布、检查器、四模式主体仍集中在一个文件，后续改动成本高。
2. **生成模板硬编码**：`generated_app_runtime.rs`（约 351 KB）等模块以内嵌字符串生成目标应用源码，可定制性差。
3. **UI 文本审计未清零**：多分辨率下仍有 text-overlap / horizontal-clip / vertical-clip。
4. **无障碍与键盘覆盖不足**：自动化只能验证 DOM 标记与部分冒烟，读屏措辞、读序、折叠区遍历、高对比焦点仍需手测清单。
5. **Bundle 体积**：Vite 大 chunk 警告已知，未做代码分割。
6. **后端集成偏 Rust-first**：C++ FFI / sidecar 有脚手架，完整「插件式」流程未闭环。
7. **测试深度**：契约脚本体量大、偏 UI 标记断言；Rust 单元测试覆盖有限。

---

## 2. 目标

在保持「桌面 IDE 手感」主线的前提下：

1. **降改动成本**：拆分巨石组件，让功能开发可并行、可回归。
2. **清体验债**：UI 审计问题归零，键盘/无障碍形成可重复验收标准。
3. **加固生成链路**：模板可定制、生成产物可验证、bundle 可控。
4. **补深能力**：后端集成、发布自动化、测试分层从「能跑」到「可交付」。

**成功度量（建议）**

| 指标 | 当前基线 | 阶段目标 |
|------|----------|----------|
| `BuilderShowcase.tsx` 行数 | ~54,800 | 阶段一 ≤ 40,000；阶段三 ≤ 20,000 |
| `ui-text-audit` 问题数（默认视口） | 见 `output/ui-audit/ui-text-audit.json` | 全视口 clip/overlap = 0 |
| 无障碍手测清单 | 无正式清单 | 有清单 + 每版本抽测记录 |
| `npm run build` 大 chunk 警告 | 存在 | 主入口可懒加载分片后显著减小 |
| Rust 测试 | 少量 `#[cfg(test)]` | 生成/持久化/构建核心路径有单测 |

## 3. 工作流拆解

### 工作流 A — UI 密度与文本审计清零（体验）

**目标**：所有官方支持视口下无 text-overlap / horizontal-clip / vertical-clip；选择条、左轨运行区、输出 Dock 在窄宽下可读可点。

#### A1. 建立「审计 → 修复 → 回归」闭环

| 任务 | 说明 | 验收 |
|------|------|------|
| A1.1 固定审计基线 | 跑 `output/ui-audit/run-ui-text-audit.mjs`，把 `ui-text-audit.json` 当前 issue 做成勾选清单 | 清单入库（可追加到本计划附录） |
| A1.2 按控件簇分组 | 左轨（left-run-controls）、选择条（selection-action-bar）、输出 Dock（output-dock）、顶栏（editor-tabs） | 每簇有 owner 与修复顺序 |
| A1.3 把文本审计并入验证习惯 | 修完 UI 跑一次 text audit + 相关 `check:*` | PR 模板或开发笔记写明 |

#### A2. 已知高优先级问题（来自 `ui-text-audit`）

| ID | 区域 | 现象 | 建议方向 |
|----|------|------|----------|
| A2.1 | 左下运行区 | `0/5 完成…` 与「调试工作台」标题 text-overlap | 窄轨改为单行摘要或省略号；kit 卡片与 plan-summary 分层 |
| A2.2 | 输出 Dock 最小化条 | `日志` 与 `就绪 / 反馈已就绪 / 问题 / 任务` 重叠 | 标签与摘要分离布局；宽度不足时隐藏次要计数 |
| A2.3 | 选择操作条 | `框选 拖拽 加选…` horizontal-clip；溢出菜单 vertical-clip | 已有 overflow 滚动时校验 sticky summary；快捷键 chips 可折叠 |
| A2.4 | 顶栏文档 chip | `1 UI · 1 文档` 与 Project dock tab 重叠 | 合并状态 chip 宽度上限 / 截断策略 |
| A2.5 | 组件按钮提示 | 双击提示与组件文字 overlap | 提示改为悬浮或仅在 hover 显示 |
| A2.6 | 1100px 紧凑视口 | 选择条命令区纵向裁切 | 紧凑断点下强制 overflow 菜单 |

#### A3. 密度收尾（对齐 Qt Creator 节奏）

近期提交已大量做 compact/flatten。收尾建议：

- 确认四模式默认打开即「摘要可见、详情按需」，无幽灵隐藏高度（参考 goal-audit Step 72 的 `hidden-until-open` 模式）。
- 统一 `data-builder-*-density` 标记命名，方便冒烟脚本断言。
- 侧 Dock 底部 clearance（输出 Dock 避让）在所有模式复用同一套计算。

**相关文件**：`src/components/showcase/builder/*`、`BuilderShowcase.tsx` 中 selection/output-dock/left-run 相关段、`output/ui-audit/`。

### 工作流 B — 架构拆分与可维护性

**目标**：`BuilderShowcase.tsx` 减负，领域逻辑进 `builder/` 模块，巨型 UI 切片独立文件；不破坏 `check:components` / `check:experience` / `check:builder-runtime`。

#### B1. 拆分策略（建议顺序）

```text
阶段 B1（低风险壳）
  layout/ 工具条与 Dock 壳 → 已有 ProjectDock/InspectorDock/LogicWorkspace/BuildWorkspace
  抽出：ModeRail / SelectionActionBar / OutputDock / CanvasToolbar / EditorTabs

阶段 B2（领域状态）
  画布交互状态（缩放、平移、框选、智能参考线、拖放）
  撤销/重做历史
  选择与层级导航
  属性检查器字段元数据与校验

阶段 B3（模式页）
  Project 工作区树 + 节点详情
  Logic 资源大纲 + 命令/槽/诊断
  Build 就绪检查 + 发布流水线 + 运行时工作台

阶段 B4（行为模块收束）
  把 builder/*.ts 中纯函数与状态机与 React 组件边界对齐
```

#### B2. 具体任务

| 任务 | 说明 | 验收 |
|------|------|------|
| B2.1 禁止再向 BuilderShowcase 新增长代码块 | 新功能必须落在 `builder/` 或新文件 | code review 约定；可选 lint/size 脚本 |
| B2.2 抽 `SelectionActionBar` | 含 idle/single/multi 三态与 overflow | 相关 check 通过；UI 审计 A2.3 不回归 |
| B2.3 抽 `OutputDock` | 最小化条、标签、任务/问题/日志 | A2.2 不回归 |
| B2.4 抽画布交互 hook | `useCanvasInteraction`（指针、框选、guides、zoom） | 行为冒烟 `check:builder-runtime` 通过 |
| B2.5 类型边界整理 | `builder/types.ts` 已很大，按域拆 `types-project.ts` / `types-release.ts` / `types-canvas.ts` | 导出兼容、编译通过 |
| B2.6 文档化模块地图 | 本计划或 `docs/architecture.md` 写清职责 | 新人能定位「改 X 去哪」 |

#### B3. 风险控制

- 每次只抽一个可见面板，抽完立刻跑：`npm run build`、`npm run check:builder-runtime`、（有桌面时）`npm run verify:desktop`。
- 不要在拆分同时改行为；行为变更另开提交。
- 保留 `data-builder-*` 标记，冒烟脚本依赖它们。

### 工作流 C — 生成链路与模板可定制

**目标**：生成的 Tauri 目标应用更丰富、可扩展；模板不再是一团巨型字符串；生成文件 diff/落盘行为可预期。

| 任务 | 说明 | 验收 |
|------|------|------|
| C1. 模板外置或分段 | 将 `generated_app_runtime.rs` 中 vite/tsconfig/main/App/styles 拆为可读片段（模板文件或清晰常量模块） | 单文件显著变小；生成物字节级对比通过 |
| C2. 组件生成代码升级 | 按组件类型输出更完整的 props / 事件 / 插槽 | `check:components` 覆盖 palette、编辑器、runtime 三端 |
| C3. 模板定制点 | 项目名、包名、依赖集、样式主题、窗口 chrome 等可配置 | 项目 schema 有对应字段并持久化 |
| C4. 增量写盘策略确认 | `incremental_io` 已避免无变更重写；补充「用户手改生成文件」策略（create-only starter 已有） | 文档 + 测试覆盖冲突场景 |
| C5. 生成窗口校验扩展 | `generated_window_validation` 覆盖更多 chrome/titlebar/窗口类型组合 | 与 Release 配置项一致 |

### 工作流 D — 键盘导航与无障碍

**目标**：形成可重复的无障碍验收，缩小「DOM 有标记」与「真实可用」之间的差距。

| 任务 | 说明 | 验收 |
|------|------|------|
| D1. 建立手测清单 | 焦点环、Tab 序、快捷键、折叠 disclosure、图标按钮名称、读屏短语 | `docs/` 下有 checklist 模板 |
| D2. 焦点与工具条 | 选择条、画布、Dock 标签、命令面板 | 无焦点陷阱；Esc/快捷键符合文案 |
| D3. 折叠区 | 默认 collapsed 的 readiness、manifest、runtime console 等 | 展开后才进入 Tab 序；Summary 有 aria |
| D4. 紧凑视口键盘 | 1100px 下 overflow 菜单、PageUp/Down/Home/End | 与 A 工作流一起验收 |
| D5. 高对比 / 焦点可见 | 侧 Dock 底部、浮层边缘 | goal-audit 中 accessibility limit 条目逐条关闭或降级为「接受并记录」 |

**说明**：goal-audit 每一步的 “Accessibility limit” 多为同类问题，D 工作流应统一消化，避免每轮 UI 密度改动重复欠债。

## 7. 风险与约束

| 风险 | 影响 | 缓解 |
|------|------|------|
| 巨石文件拆分引入行为回归 | 画布/选择手感变差 | 只搬家不改行为；小步提交；跑冒烟 |
| UI 密度与审计互相打架 | 修 overlap 又制造 clip | 固定审计视口集合；一次改一簇 |
| 生成模板改坏产物 | 目标应用编译失败 | 生成前后 diff + `check:runtime-contract` |
| 契约脚本过大难维护 | 假绿/难调试 | 拆 helper；失败信息带 DOM 标记 |
| alpha schema 变更 | 旧项目打不开 | 版本字段 + 迁移函数 + 文档 |
| 只做 UI 收紧不修架构 | 短期好看长期更贵 | 阶段 1 强制架构配额 |
