# 界面密度：让「简单易用」可测

> 目标是 Qt Creator 那种安静：屏幕上以**操作**为主，状态只在需要动手时才染色。
> 这篇记录衡量口径、每轮的数字，以及为什么这么定。

## 为什么要量

「简单易用」如果只是感觉，就没法验证「还有没有可优化的地方」。所以把它拆成三个能在无头浏览器里算出来的数：

| 指标 | 含义 | Qt Creator 的样子 |
|------|------|------------------|
| `chips` | 视口内**可见**的圆角状态小标签（≤28px、短文本） | 少：只有异常和进行中 |
| `controls` | 可交互控件数 | 多：全是能点的东西 |
| `textChars` | 可见文本字符（只算叶子文本） | 少：没有解释性长句 |

`chip / controls` 是核心比值——装饰多过动作，就是「难扫读」。

## 口径细节（踩过的坑）

1. **只算真正画出来的**。`.sr-only` / `aria-hidden` / 无布局尺寸的元素不计。
2. **闭合的 `<details>` 不计**。它对内部节点报非零 rect，但屏幕上根本没有。早期版本把折叠面板里的 chip 全算进来了，数字虚高 4 倍。
3. **文本只算叶子节点**。`textContent` 在父元素上会重复整棵子树，按深度累加会把数字乘上嵌套层数。
4. **测两种状态**：`collapsed`（首屏印象）与 `expanded`（展开全部后的作业态）。两态预算不同。
5. **量整个工作区，不量视口**（`[data-builder-density-root]`）。滚动不该改变答案：一个面板不会因为把装饰挤到折叠线下就变安静。标题栏、状态栏、模式栏、底部 Dock 是稳定外壳，各模式共担，算进去会淹没工作区噪音。这个根由 `ShellView` 在四种模式下统一挂上，值就是当前模式名；探针同时断言它，测错工作区会直接失败。早先探针借用的是 `data-builder-readable-workbench`——那个属性只在 design 模式存在，另外三个模式静默掉到 `document.body`，把外壳也量了进去，四个数字根本不可比。**测量根缺失时抛错，不做兜底**：兜底就是把「探针没接上」伪装成「界面很安静」。
6. **鼠标点击是命中测试的**。CDP 的 `Input.dispatchMouseEvent` 和真实鼠标一样会被遮罩吃掉。首屏引导的全屏遮罩一开，模式栏的点击全落到弹窗上，四个工作区测出来是同一个数字。现在 `clickCenter` 会先做命中测试，被挡住就报出是谁挡的；关弹窗也带断言，关不掉直接失败，而不是默默测错界面。
7. **chip 是叶子装饰，不是装了按钮的圆角行**。探针曾经把工具条行、组件收藏行算成 chip——它们是布局，不该记在「装饰」头上。凡是含可交互控件的元素都不是 chip。
8. **圆角阈值不能是「药丸」**。早先要求 `borderRadius >= height/2`，于是每个 `rounded-md` 徽章都被漏掉，探针把一个花哨的工作区报成安静。任何非零圆角都算。
9. **布局契约和测量根不能是同一个属性**。`data-builder-readable-workbench="qt-creator"` 是 design 工作区的排版契约（`check-editor-experience` 会查它），不是密度探针的根。两者共用一个属性时，design 之外的模式会静默换口径。测量用独立钩子 `data-builder-density-root`，并断言它的值等于当前模式。

## 当前基线（1440×960，量整个工作区）

| 工作区 | collapsed chips | expanded chips | selected chips | expanded 装饰/动作 | expanded 字符 |
|--------|----------------:|---------------:|---------------:|-------------------:|--------------:|
| project | 4 | 7 | 7 | 3% | 4934 |
| design | 0 | 0 | 0 | 0% | 1095 |
| logic | 0 | 2 | — | 2% | 3162 |
| build | 3 | 12 | — | 5% | 16684 |

`selected` 是真正的工作态：面板全开 + 选中一个控件，检查器才挂载。空画布比任何人在上面编辑时都安静，只量空态会得到一个门禁永远输不了的结论。design 的画布在门禁里是空的，所以探针会先从组件面板种一个控件——那正是用户第一分钟会做的事。

剩下的每一个 chip 都是**需要动手的状态**：`待构建`、`待生成`、`待保存`、`待同步`、`未保存`、`未连接 UI`、`未使用`、`等待构建`、`需复核`、`无 exe`、`N 警告`、`N 个问题`。设计面三种状态已经一个 chip 都不画。

预算按实测收紧在 `DENSITY_BUDGETS` / `EXPANDED_BUDGETS` / `SELECTED_BUDGETS`，只允许下调。build 的 `提醒`×23 / `警告`×7 现在是**正文**不是 chip——那是待办清单，要减的是打开的项数，不是把它藏起来；只有阻塞项（`阻塞`/`错误`/`失败`）还留药丸。

`check:ui-density:report` 会打印重复标签直方图，每条带最近的 `data-builder-*` 钩子名，直接指向调用点，不用再猜。画布节点（`[data-builder-node-id]`）子树不在测量范围内——那是用户正在设计的产品，不是 Nova 的外衣。

## 规则：什么时候该染色

新写状态标签前先问一句——**用户需要因此动手吗？**

- **要动手** → 染色：`未保存`、`待生成`、`待构建`、`运行中`、`失败`、`缺失`、`未连接 UI`、`3 个槽待生成`。
- **不用动手** → 只进无障碍树（`sr-only`），不占视觉：`就绪`、`空`、`已同步`、`已完成`、`正常`、`无`、`待开始`、`通过`，以及计数为 0。中文状态是「名词 + 状态」（`槽函数就绪`、`全部同步`），名词只说哪个面板没事，**结尾是例行词就整条例行**；但带「待/未/缺/需/不一致」的仍是信号，`待开始` 这种例行排期除外。
- **计数一律做正文读数** → `9 项`、`27`、`1 UI · 1 文件` 是读数不是状态。折叠区的计数不再用「折叠时染色」那套——`group-open:hidden` 是 `display:none`，会把内容从无障碍树里一起摘掉；正文在折叠时同样醒目，展开时也不重复。
- **读数不是状态** → 分数百分比、坐标、版本号、哈希、进度值用等宽纯文本。它旁边多半已经有图标或进度条在表达严重程度，再包一层圆角是花视觉预算买重复信息。
- **类别不是状态** → 存储归属（`源码` / `生成` / `.nova`）、类型名（`string` / `必填`）、事件种类、scope 名（`rust` / `release`）是表格列值，做正文文本，不做药丸。
- **未知标签默认当读数** → 没人分过类的东西不该先花一笔视觉预算；分类之后再决定。
- **已经用别的手段说过的不再说一遍** → 选中行有底色和 `aria-current`，就不再挂「当前」；文件名旁的保存状态只在未保存时才是药丸。

实现落在 `src/components/showcase/builder/view-labels.ts`（纯函数，门禁可直接单测）与 `view-helpers.tsx`（组件）：

- `SignalChip` — 显式传 `signal`，不适合时退化为 `sr-only`。
- `StateBadge` — 显式传 `signal` 强制染色或静音；**不传时走三分判定**，读数做正文而不是默认长成药丸。
- `StateLabel` — 自由文本的三分：信号上药丸、例行进无障碍树、读数做正文。传 `showQuiet` 时例行态做正文——**状态列里的「完成」是用户来读的数据**，既不该染色也不该藏。
- `CountReadout` — 计数读数；为 0 时连正文都不占视觉。要让 0 真的隐去必须传 `count`；只传 `label` 时组件无从判断。
- `SIGNAL_STATE_LABELS` / `isSignalStateLabel` — 「必须动手」白名单 + 片段（`待`/`未`/`缺`/`需`/`不一致`）。用片段而不是「不安静就染色」，因为同一个状态字段下会并排出现「待生成」和「尚无版本」，两者不该同一个重量。
- `isQuietStateLabel` — 精确表 + 结尾例行词，且先让过信号。
- `isReadoutStateLabel` — 既非信号也非安静，就是读数，做正文。

**wire 值要先翻译再判定。** `ProjectActivityEntry.status` 之类是 `"built"` / `"saved"` 这种英文，拿去比中文安静集合永远不匹配，例行项会一直带着 chip，还会把英文漏进中文界面。先过 `projectActivityStatusLabel` / `projectChangeScopeStatusLabel` 这类映射，再做安静判定。

信息不丢：`sr-only` 仍在无障碍树里，读屏照读；`data-builder-*` 钩子挂在同一个节点上，既有测试不受影响。

## 怎么跑

```bash
npm run check:ui-density          # 门禁：超出预算即失败
npm run check:ui-density:report   # 只打印，含重复标签直方图
npm run check:ui-density-rules    # 门禁判定逻辑自身的回归测试
```

两者都已并入 `npm run check:experience`，也就是 `npm run build` 的前置。

判定逻辑单独成一个测试，是因为 `findDensityOverages` 一旦写错，就会把装饰过度的界面报成「安静」，而且不响。预算数值从表里推导而不是写死在测试里，这样每轮收紧预算不会让用例跟表打架。

**门禁要量它声称的东西。** `check:a11y` 的 6.7 长期报「中文界面无未翻译英文」，而界面里一直有五十多条英文——它只量当前渲染的 DOM，跑在 200% 缩放留下的 720×480 视口上（响应式隐藏的内容整片看不见），而检查器要选中控件才挂载。一个只看首屏空态的检查，和只量空画布的密度探针是同一个缺陷：它输不了，所以不算数。现在两者量的是同一套状态（四模式 × 折叠/展开/选中），判定里再把技术标识符（文件名、`logic.rs:12`、camelCase 字段名、Rust 源码面、组件目录类型名）摘出去，剩下的才是真漏译。

## 预算怎么定

钉在实测值附近留少量余量：**加装饰会挂，加功能不会**。往下改了一档就把预算收紧，防止回潮。

## 还能往哪推

- build 展开态 16684 字符是四屏最重的。注意口径：`EXPAND_DISCLOSURES` 会打开**所有** `<details>`（含嵌套），所以「把长句折进默认折叠的详情」并不能降低这个数——展开态按定义就是全开的上限，要减只能删内容。真正该盯的是折叠态的 74 字符，以及用户实际会打开哪几个面板。
- 组件面板的目录名仍是英文类型名（`Spin Box` / `Assist Chip` / `Elevated Card`），描述是中文。类型名按「类别不是状态」当读数处理，和 `QPushButton` 一个道理；若要彻底中文化，是改目录文案，不是改判定规则。
- build 展开态的警告计数有三处（`1 警告` / `5 警告` / `9 警告`），分属窗口视觉 / 构建就绪 / 发布就绪三个审计域，三个数字不同是**对的**。每处紧挨着自己的标题卡，域上下文在；给计数再加「视觉/构建/发布」前缀会和卡片标题说两遍，所以不动。若日后三个卡并排，再考虑前缀。
- `待生成` 在 project 展开态出现 3 次，是来源表里三行各自的状态列取值——那是用户来读的数据，不是重复的装饰。折叠次要行会把待办藏起来，方向反了。
- 工作台与跳转面板的裸 `<Badge>` 已经清零，全部走 `StateLabel` / `StateBadge` / `CountReadout`。对话框（冲突合并等）里还有少量原生 `Badge`，属对话框自己的密度，不在工作台预算内。
- 逻辑工作区没有「选中」概念，`selected` 态暂无测量值；若日后加入节点选中，需给 `SELECTED_BUDGETS.logic` 补预算，否则门禁会以「量到了没得判」为由失败——这是故意的。
- `check:showcase-size` 现在 19940/20000 行，只剩六十行余量，再往 `BuilderShowcase.tsx` 加东西就会顶到上限。
